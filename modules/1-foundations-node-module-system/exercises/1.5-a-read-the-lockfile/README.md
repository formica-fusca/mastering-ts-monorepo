# 1.5-a — Read the lockfile

**From:** lesson 1.5, lockfiles and deterministic installs.

## Goal

`tree/` is a two-package pnpm workspace with a real `pnpm-lock.yaml`, generated by pnpm 11.9
and frozen. No `node_modules`, nothing to install. Answer the eight questions in
`predictions.json` **by reading the lockfile and the three manifests**.

```
tree/
  package.json                devDependencies: typescript 5.9.3
  pnpm-lock.yaml              ← the subject
  packages/web/package.json   dependencies: semver ^7.5.0, is-odd 3.0.1
  packages/api/package.json   dependencies: semver ^6.0.0, is-number 7.0.0
```

`predictions.json` is the only file to edit.

## The constraint

**Do not run pnpm.** Every answer is in the file. Running the package manager would tell you
what it does; the exercise is whether you can tell what it *will* do from the record it left.
Do not modify `tree/`; the verifier hashes it.

## Verify

```bash
node verify.mjs
```

One check guards the tree, eight compare your answers.

## Hints

<details>
<summary>Hint 1 — which section answers which question</summary>

Versions per package: `importers`. Who depends on what: `snapshots`. What exists in the
graph at all: `packages`. Questions 1, 2 and 6 are `importers`; 3 is `packages`; 4 and 5 are
`snapshots`, walked downward from a `semver` entry.
</details>

<details>
<summary>Hint 2 — question 5</summary>

Removing a dependency removes everything that *only* it was holding in the graph. Follow
`semver@7.5.4` down through `snapshots` and ask, for each thing you reach, whether anyone
else still wants it. Then check whether the *other* semver is affected at all.
</details>

<details>
<summary>Hint 3 — questions 7 and 8</summary>

`--frozen-lockfile` compares the `specifier` lines textually against the manifests. Whether
the locked version happens to satisfy the new range is not part of the check. And a locked
version is a locked version: nothing published tomorrow changes an install that reads this
file unchanged.
</details>

## What this is really testing

Whether you can treat the lockfile as what it is, the record of a resolved graph, and read
versions, ownership, and consequences off it directly, rather than treating it as noise that
the package manager owns.
